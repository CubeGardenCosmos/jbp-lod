## Present in source

- VMA-backed `GpuBuffer`, staging, Synchronization2 helpers, nonblocking completion/retirement and `LodGpuBuffers`/`LodFrameBuffers` slot ring exist. Allocation, resize preservation, submission ordering and destruction safety remain runtime-unproven.
- CPU section/quad/indirect/model/uniform ABI types, section packing and CPU prep/prefix references exist. CPU references do not establish GPU correctness.
- `compute/LodComputeExecutor.java:295-346` now records a pass graph, not merely a pipeline wrapper: HiZ callback, uniforms/clears, visibility operations, hierarchical ping-pong traversal, preparation, cull-visibility callback, command generation/prefix/translucent generation, optional cleaner and final consumer/host barriers. Descriptor and optional-subgroup selection code is present. Nonzero indirect output and algorithm equivalence remain unproven.
- `vk/gpu/HizPyramid.java` owns an R32F image generation, per-slot descriptors, mip-0 depth blit, compute mip chain/small-image blit schedule, barriers, sampled descriptor and replaced-generation retirement. `VulkanLodRenderer.FrameHooks` connects depth conversion → HiZ → traversal and cull raster → command generation outside the game's rendering scope. No GPU reduction or occlusion result has been observed.
- `data/tree/` contains `NodeStore`, `NodeManager`, `SectionGeometryManager`, watchers/router, distance/ring tracking and asynchronous `LodNodeService`; it accepts top-level changes, child changes, geometry results, traversal requests and cleaner removals and publishes `SectionDelta`. `LodNodeGpuBuffers` uploads those deltas. `LodRuntime` connects camera updates, uploads, visibility operations and retired request/cleaner decoding.
- `JbpLodClient` opens the scope/storage/node session on its dedicated storage executor, rejects superseded opens, and coordinates game-thread publication/teardown with the live producer. Reopening waits for the prior scope release; dimension identity changes reopen the dimension-specific session. Lifecycle correctness remains runtime-unproven.
- `LodSession` installs `compute.SectionMesher` into `StoredSectionMeshProvider`. `SectionMesherCore` ports upstream `RenderDataFactory` face generation and `ScanMesher2D` merging: opaque/nonopaque/fluid paths, neighbor culling, packed lighting/biomes, AABB and eight face-order ranges. Mesh workers read neighboring storage sections; unavailable model publications defer/retry rather than fabricate empty geometry. Model-generation changes invalidate requested meshes.
- `LiveChunkCapture` tracks loaded/dirty chunks even while the scope opens, captures bounded dirty chunks per tick and captures unloading chunks. Fabric load/unload events and a `ClientLevel` dirty-section hook feed it. Immutable block/biome/light snapshots cross to `LiveSectionProducer`; ID/NBT mapping, voxelization, storage and hierarchy work run on its dedicated worker.
- `VoxelHierarchy` retains upstream opacity-first mip selection, XYZ tie priority and all-air light averaging. A captured 16³ section replaces one octant of a stored 32³ section and propagates through all LOD levels while retaining stored siblings. Writes call `LodNodeService.onSectionUpdated`; six adjacent sections receive geometry invalidations for seam culling.
- `StoredVoxelSection` stores exactly 32768 little-endian packed voxel longs in `x | z << 5 | y << 10` order. This is JBP-LOD's explicit opaque-storage payload, **not** upstream `SaveLoadSystem3` compressed file compatibility; packed voxel and quad semantics derive from upstream.
- RocksDB JNI 10.2.1 desktop selection and Android boundary remain documented in [V3-storage-decision.md](V3-storage-decision.md). Android ABI/bionic/16 KiB suitability is unverified.

## Review fixes in source (not runtime-verified)

- Live producer shutdown (review F1): `LiveSectionProducer.closeAsync` closes capture admission first. Queued capture work observes the closed state and skips; the sentinel and shutdown follow the queue drain.
- Storage shutdown (F2): `JbpLodClient` waits for every pending scope release. Each release is handled individually, so one failure cannot complete the barrier early. On timeout it logs a WARN and leaves `STORAGE_IO` running instead of shutting it down under a pending release.
- Mesh failures (F5): `StoredSectionMeshProvider` retries a failed build after 250 ms, then 1 s. After three attempts it logs a WARN, enters a 5 s cooldown, and calls `LodNodeService.submitRequestFailed`. The worker then cancels the pending child request (`NodeManager.processRequestFailure`), so traversal re-requests later. Failed meshes never submit geometry.
- Capture backpressure (F6): `CaptureAdmission` bounds captured-but-unvoxelized sections at 512. `LiveChunkCapture` pops a dirty chunk only when capacity covers all of its sections. Unload-path drops are counted and WARNed once per JVM. Dropped unload sections are recaptured only when the chunk reloads.
- First-activation INFO logs (once per JVM): `[JBP-LOD] First chunk captured`, `First section hierarchy stored`, `First section meshed` (with quad count), `First node publish` (with node, metadata and quad-upload counts).
- Unit tests written, not executed by this slice: `CaptureAdmissionTest`, `MeshRetryPolicyTest`.
- Known limits: the capture-drop WARN fires once per JVM; the cooldown uses `System.nanoTime`-based timestamps; `MeshRetryPolicy.BACKOFF_MILLIS` length must equal `MAX_ATTEMPTS - 1`.

### Fixes in source

1. `data/ingest/VoxelHierarchyWriter` — extracted from `LiveSectionProducer.writeHierarchy` and now
   shared by live capture and the importer. Its `write` is synchronized: each level's
   read-modify-write retains sibling octants, so two capture threads (live + two import workers)
   cannot lose each other's updates.
2. `importing/RegionFileLayout` — pure Anvil header parsing, region-name/coordinate parsing,
   chunk-coordinate derivation and sector/length validation. Invalid or oversized entries are
   skipped, never allocated.
3. `importing/RegionChunkReader` — streams one chunk at a time from `FileChannel` (8 KiB header,
   4 KiB sectors), validates the length/sector bounds and copies only the compressed payload.
4. `importing/WorldImporter` — background importer, ported from upstream `WorldImporter`:
   one coordinator + two daemon workers, a 16-entry bounded payload queue and a 4 MiB per-chunk
   payload cap (worst case ≈ 64 MiB compressed data). It applies `DataFixers`, accepts `FULL` and
   `EMPTY` status, parses `block_states`/`biomes` with `PalettedContainerFactory` codecs, defaults
   absent biomes to plains, reads `BlockLight`/`SkyLight` layers, voxelizes exactly like live
   capture (`sky | block << 4`, quart biomes) and writes all five hierarchy levels through
   `VoxelHierarchyWriter`. Per-chunk failures are counted and limited to 20 log lines; the import
   continues.
5. `importing/DefaultBiomeContainer` — the upstream uniform-plains `PalettedContainerRO` used when a
   chunk section has no biome payload.
6. Triggers:
   - `/jbplod import current` (client command, current single-player dimension's `region` folder);
   - `/jbplod import status` and `/jbplod import cancel`;
   - `-Djbp.lod.importWorld=true` imports the current single-player dimension automatically when the
     dev scope session opens.
   Only the region path and `RegistryAccess` are resolved on the game thread; listing, I/O, NBT and
   voxelization run on the importer threads. Import writes become visible through the existing
   `LodNodeService.onSectionUpdated` path: the level-4 child-existence update makes traversal request
   the newly stored children; models bake via the existing `ModelProvider` miss path.
   Teardown only cancels the importer. Already queued storage operations precede the close operation
   on the single I/O executor; later writes fail and end the worker, so neither the render thread nor
   the storage executor is blocked.
7. `vk/render/LodFogPolicy` + `MixinFogRenderer` — port of upstream `MixinFogRenderer`. While the
   renderer is enabled and a scope runtime is active, vanilla environmental and render-distance fog
   are pushed out of range. Previously Sodium's vanilla fog (tuned to hide the loaded-chunk edge) was
   applied to LoD fragments too, painting everything beyond the vanilla fog end in the fog/sky
   colour — the "far ground beyond the vanilla fog edge is sky" symptom in normal (non-debug) view.
   With the runtime inactive or `-Djbp.lod.render=false`, vanilla fog is untouched.
8. `build.gradle` adds `compileOnly "org.jspecify:jspecify:1.0.0"` because Minecraft 26.3 class
   files reference `org.jspecify.annotations.Nullable`; without it javac cannot load
   `PalettedContainerRO`.

## Sky-light capture defaults for derived light layers (2026-10-19)

The llvmpipe RD2 run in V4 reported black blocky patches over water and dark blobs on sunlit terrain.
The `light` debug view showed 0% pure black but ~26% dim (lightmap 14-24/255), and ingest counted
`noSkyLayer=16432 skyZero=8742 skyFull=1649` of 28,614 sections. The defect is in the light snapshot,
not in the atlas or the composite.

### Root cause (vanilla 26.3 light engine)

`LayerLightEventListener.getDataLayerData` returns `null` for sections whose sky light the engine derives
instead of storing. `SkyLightSectionStorage.getLightValue` returns 15 at or above the column's top
light section (and repeats layer 0 of the nearest section above when a below-top section has no data
layer); it does not return darkness. `LiveSectionProducer` mapped that `null` to sky light 0, and the
section mesher copies the adjacent air voxel's `sky | block << 4` onto every face, so air above the
terrain and water was stored black and blackened the faces below it. Chunks are also visible to
`ClientChunkEvents.CHUNK_LOAD` before `ClientPacketListener.applyLightData` queues their light
packet, so the first capture of a chunk could see missing layers and zero data.

### Fix in source

- `data/ingest/SkyLightFallback` — pure helper mirroring the sealed engine:
  `ready(onlyAir, sky, block)` says a non-air section may only be captured with both layers present;
  `resolve(x, y, z, maxSectionY, source)` returns 15 when no section above has a layer and otherwise
  reproduces `repeatFirstLayer` (layer 0 copied into all 16 layers) from the nearest section above
  that has one. Block light has no implicit default and stays 0 when absent.
- `LiveSectionProducer.capture` — first pass gates the chunk on `SkyLightFallback.ready` for every
  non-air section; a not-ready chunk is not consumed and the caller retries. The snapshot pass applies
  `SkyLightFallback.resolve` for absent sky layers before the layer is handed to the worker, and the
  ingest stats distinguish raw absence (`noSkyLayer`) from applied default (`skyDefaulted`).
- `LiveChunkCapture.tick` — a dirty chunk that returns not-ready stays dirty (bounded two chunks per
  tick as before), so capture happens after the light packet instead of on the load event. The
  existing `ClientChunkCache.onLightUpdate` dirty hook still re-captures chunks after later light
  updates.
- `importing/WorldImporter` — saved chunks omit `SkyLight` under the same rule; missing tags are now
  resolved with `SkyLightFallback.resolve` over the chunk's own section list before voxelization.
- `runtime/LodStats` — `light[...]` adds `skyDefaulted` (sections that needed the derived default) and
  `deferred` (capture attempts skipped because the light packet had not been applied); `skyZero` and
  `skyFull` now describe the light actually ingested (after the default), not only raw layers.

(not farthest) above section wins; the

### Correction: the residual was not the black-mass cause (2026-10-19)

The last paragraph above called the level≥1 zero air-light "not part of this light-snapshot fix" because
upstream `Mipper` selects an opaque child in a mixed cell. The selection itself is indeed faithful
(re-verified line by line, including the x > y > z tie bits), but visible faces do not use a mixed
cell's light: mixed cells are opaque and their faces are culled, and a rendered face reads the
neighbouring pure-air cell. The black masses came from the two places where jbp created *missing*
data as air at sky 0 instead of upstream's air at sky 15:

- `SectionMesher` used `new long[32768]` for a neighbour section that storage does not contain;
  upstream `ActiveSectionTracker.acquire` fills a storage miss with
  `Mapper.composeMappingId((byte) 15, 0, 0)`.
- `VoxelHierarchyWriter` allocated a zero array for a never-written section; upstream creates the
  section through the same acquire path (air/sky-15) and only then inserts the chunk octant.

Both are fixed in this slice. On the deterministic camera the pure-black share inside LOD pixels fell
from 24.86% (matched pre-fix rerun) to 12.24% with the neighbour fallback and to **0.02%** on a fresh
cache written by the fixed code; see V4 "Black hillside masses: missing-section and new-section light
semantics" for the per-level table, the offline octant counts and the screenshot paths. Caches written
before the fix still contain the zero octants and need a fresh capture/import.
