# JBP-LOD V0 evidence

Date: 2026-10-18. Scope: JBP-LOD V0 and the development-only singleplayer scope extension. No LOD renderer behavior is claimed.

- Host: `WS-RTX3060` (JUnit XML hostname), Linux WSL2 (`6.18.33.2-microsoft-standard-WSL2`, x86_64); OpenJDK 25.0.4.1.1.
- Build: Gradle wrapper 9.8.1, Fabric Loom 1.18.3, Minecraft 26.3, Fabric Loader 0.19.5, Fabric API 0.162.0+26.3, Sodium 0.9.2+mc26.3.

- Original V0 baseline: `BUILD SUCCESSFUL`; 6 tests, 0 failures/errors/skips. The final source/config build after the dev-scope changes is recorded below. The JAR is `mods/jbp-lod/build/libs/jbp-lod-0.1.0.jar`.
- Baseline logs: `mods/jbp-lod/run/evidence/v0-gradle.log`; baseline JUnit XML: `mods/jbp-lod/build/test-results/test/TEST-cn.cubegarden.cosmos.jbp.client.lod.scope.LodScopeManagerTest.xml` (updated by the final run below).

## Vulkan-only dev-client loading smoke

- Host/device: same WSL2 host. Minecraft selected Vulkan with Mesa llvmpipe (`Mesa 26.2.3`, LLVM 22.1.8, 256-bit); SDL created a Wayland window. Device: `llvmpipe (LLVM 22.1.8, 256 bits)`.
- Command: `JAVA_HOME=/usr/lib/jvm/java-25-openjdk SDL_VIDEO_DRIVER=wayland JAVA_TOOL_OPTIONS='-Djbp.lod.dir=/tmp/jbp-lod-v0-cache' timeout 180s ./gradlew runClient --args='--graphicsBackend vulkan --width 1280 --height 720 --username JbpLodV0 --uuid 00000000-0000-4000-8000-000000000001 --accessToken offline --userType legacy' --console=plain`.
- Result: Fabric loaded `jbp-lod 0.1.0`; log recorded `[JBP-LOD] Initialized V0 client scope support`. The forced Vulkan backend created a window and entered an integrated singleplayer world; the JBP-LOD log then recorded `Inactive: singleplayer sessions do not have a node scope.` The command ended with exit 124 because the explicit 180-second timeout stopped the still-running client; it was not a normal shutdown test.
- The log reports that the Microsoft D3D12 Vulkan device did not satisfy Minecraft's base feature set (`VK_KHR_push_descriptor` missing); Minecraft continued on Vulkan llvmpipe. This proves Vulkan client loading on the WSL software device only, not on a Windows/Linux hardware driver. Khronos Vulkan validation is not installed in this environment.
- Logs: `mods/jbp-lod/run/evidence/v0-vulkan-client.log` and `mods/jbp-lod/run/logs/latest.log` (the latter includes the singleplayer inactive message).
- The first V0 client log also reported a missing `jbp-lod.refmap.json` referenced by the then-current V1 mixin config. V1 removed that unused refmap reference (its mixins use `remap=false`); the final shared source/config compile and jar task now pass.

## Development-only singleplayer scope extension

- Final build command: `JAVA_HOME=/usr/lib/jvm/java-25-openjdk PATH=/usr/lib/jvm/java-25-openjdk/bin:$PATH ./gradlew compileJava test lodJar --console=plain`.
- Final result: `BUILD SUCCESSFUL`; 10 tests, 0 failures/errors/skips. JUnit XML: `mods/jbp-lod/build/test-results/test/TEST-cn.cubegarden.cosmos.jbp.client.lod.scope.LodScopeManagerTest.xml`. Final build log: `mods/jbp-lod/run/evidence/v0-dev-scope-gradle.log`.
- Attempted Vulkan command: `JAVA_HOME=/usr/lib/jvm/java-25-openjdk SDL_VIDEO_DRIVER=wayland JAVA_TOOL_OPTIONS='-Djbp.lod.dir=/tmp/jbp-lod-dev-scope -Djbp.lod.devScope=true' timeout 180s ./gradlew runClient --args='--graphicsBackend vulkan --width 1280 --height 720 --quickPlaySingleplayer "New World" --username JbpLodDevScope --uuid 00000000-0000-4000-8000-000000000002 --accessToken offline --userType legacy' --console=plain`.
- Attempt result: Vulkan llvmpipe launched Minecraft 26.3/Fabric 0.19.5; the client entered `New World`, but logged `[JBP-LOD] Inactive: the dev scope ID cannot form a safe directory.` The lock path `/tmp/jbp-lod-dev-scope/dev/New_World/lod.lock` was absent; the command ended with exit 124 from the explicit 180-second timeout.
- The world-folder extraction was then changed to normalize the `LevelResource.ROOT` path before taking its final component; that source change passed the final compile/tests/jar above but was **not** re-run in Minecraft. **pending: game smoke deferred by user.** No log proves the dev scope activated or acquired its runtime lock; main integration must perform that smoke after rendering is complete.

## Limits / pending evidence

- No Windows or Linux hardware Vulkan client run is recorded; no LOD rendering or Vulkan validation result is claimed. The WSL client used llvmpipe after the D3D12 device missed a required extension.
- Android `Context.getCacheDir()/lod` is covered as a pure path helper only; no Android runtime/device test was run.
- The initial client smoke exercised the singleplayer inactive path, not an active scope. The attempted dev-singleplayer smoke below also did not acquire a lock; unit tests cover dev-scope lock conflict and node-scope release/reacquisition.
